1. Что такое Вайбкодинг и OpenCode

Вайбкодинг — это когда вы описываете задачу на обычном языке, а AI-агент сам пишет, запускает и правит код. OpenCode — это бесплатный open-source агент, который работает в терминале, как приложение и как расширение для редактора. Он не привязан к одной модели: можно подключить 75+ провайдеров и менять модель под задачу.

Почему OpenCode, а не Cursor/Copilot?

  • Модель-независимый. Хотите Claude сегодня, DeepSeek завтра, локальную модель послезавтра — один и тот же инструмент.
  • Бесплатный инструмент. Платите только за токены модели (или $0, если локально). Нет подписки за саму программу.
  • Open source (MIT). 150k+ звёзд на GitHub, можно читать, форкать, расширять.
  • Архитектура клиент-сервер. Go-TUI + Bun/JS HTTP-сервер. Несколько интерфейсов (терминал, десктоп, VS Code) могут подключаться к одному серверу.
  • Git-снапшоты и /undo /redo. Агент делает снимок перед изменениями — откатить легко.
  • LSP-диагностика. После правок агент видит ошибки компилятора и сам их исправляет.
  • Хранение в SQLite. История разговоров локальная, переносимая.
OpenCode не «обёртка» вокруг Claude или GPT. Это harness (обвязка), а мозги (модель) вы приносите сами. Именно поэтому смена модели — это смена одной строчки в конфиге.

Установка за 2 минуты

Linux / macOS (одна команда):

curl -fsSL https://opencode.ai/install | bash

Windows: скачайте приложение с opencode.ai или установите через npm:

npm i -g opencode-ai

Проверка:

opencode --version
opencode service status

Запуск в проекте:

cd my-project
opencode

Конфигурация (opencode.json)

Глобальная: ~/.config/opencode/opencode.json(c). Проектная: opencode.json(c) или .opencode/opencode.json(c) в корне. OpenCode ищет конфиги во всех родительских папках и мержит их.

{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/anthropic/claude-sonnet-4.5",
  "default_agent": "build",
  "permissions": { "bash": "ask", "edit": "allow" }
}
Изменения применяются без перезапуска — OpenCode следит за файлами. Принудительная перезагрузка: /reload.

2. К чему можно подключить OpenCode

OpenCode умеет работать с 75+ провайдерами. Можно использовать готовые подписки (GitHub Copilot, ChatGPT Plus/Pro), прямые API-ключи, шлюзы (OpenRouter) и локальные модели.

Подписка

MCP-серверы (инструменты для агента)

MCP (Model Context Protocol) позволяет подключать внешние инструменты: базы данных, GitHub, Slack, браузер, файловые системы, Railway и т.д. Агент сможет сам вызывать эти инструменты.

opencode mcp add <name> --global --url <remote-url>
opencode mcp list
Удалённые серверы по умолчанию используют OAuth. Если mcp list просит авторизацию — запустите /mcps, выберите сервер и войдите. Не запускайте opencode mcp auth через shell — он интерактивный.

Примеры MCP: GitHub (issues/PR), Postgres, filesystem, fetch (веб), Playwright (браузер), Railway, Sentry. Ключи храните через {env:MCP_API_KEY}, не в конфиге.

Плагины, навыки (skills) и агенты

  • Плагины — расширяют TUI и сервер: хуки, трансформы, свои инструменты. Лежат в .opencode/plugins или пакетами.
  • Навыки (skills) — папки с SKILL.md, которые агент подгружает по задаче. Удобно для повторяющихся процессов (деплой, тесты, код-ревью).
  • Агенты — можно завести специализированных: build, plan, кастомные с своими промптами и разрешениями.
  • Команды — свои слэш-команды в конфиге.
  • Форматтеры и LSP — автоформатирование и диагностика после правок.

Локальные модели (бесплатно, офлайн, приватно)

OpenCode работает с Ollama и LM Studio. Идеально для приватного кода и офлайна.

# Установить Ollama, скачать модель
ollama pull qwen2.5-coder:14b
# В OpenCode: /connect -> Ollama, или указать в конфиге
"model": "ollama/qwen2.5-coder:14b"
Локальная модель стоит $0 за токен, но нужна видеокарта (8-16 ГБ VRAM для 7-14B моделей). Качество ниже frontier, но для рутины и приватного кода — отлично.

3. OpenRouter — полный гайд

OpenRouter — это единый шлюз к 400+ моделям от 60+ провайдеров через один API-ключ и один endpoint (OpenAI-совместимый). Не нужно заводить 10 аккаунтов — один ключ, один счёт, и вы можете менять модель одной строчкой.

Зачем нужен OpenRouter

  • Один ключ на всё. Claude, GPT, Gemini, DeepSeek, Llama, Grok — всё через один API.
  • Умная маршрутизация. Если провайдер упал или упёрся в лимит — автоматический failover на другой.
  • Экономия. По умолчанию выбирается самый дешёвый стабильный провайдер для модели. Есть :floor, :nitro, auto-router.
  • Сравнение моделей. Удобно тестировать разные модели на одной задаче.
  • Бесплатные модели. 20+ моделей по $0/токен.

Подключение OpenRouter к OpenCode

  1. Зарегистрируйтесь на openrouter.ai, создайте API-ключ.
  2. В OpenCode: /connect → выберите OpenRouter → вставьте ключ.
  3. Выберите модель: /models или в конфиге:
"model": "openrouter/anthropic/claude-sonnet-4.5"
// или дешёвый вариант:
"model": "openrouter/deepseek/deepseek-v4.1-flash"

Фишки маршрутизации (главное для экономии)

Суффикс/параметрЧто делает

Prompt caching (очень важно для экономии)

На поддерживаемых моделях (DeepSeek R1, Claude, Gemini и др.) повторяющийся контекст кэшируется. Эффективная цена падает на 60-80%. Условия:

  • Стабильный префикс промпта (системный промпт + контекст проекта в начале).
  • Передавать один и тот же x-opencode-session / session ID — OpenRouter использует sticky routing, чтобы держать диалог на одном endpoint'е.
  • Не менять начало промпта между запросами.

BYOK (свои ключи через OpenRouter)

Можно подключить свои ключи провайдеров через OpenRouter — получите routing + failover + аналитику. Комиссия: 5% сверху, но в рамках бесплатного лимита (1M запросов/мес) — без комиссии. Выгодно только если ваша прямая цена минус 5% ниже каталогной цены OpenRouter.

6. Как экономить токены и не уходить за лимиты

Экономия строится на трёх китах: правильный выбор модели, кэширование контекста и контроль объёма. Ниже — конкретные приёмы.

Стратегии экономии токенов

  1. Многоуровневая маршрутизация (fallback-цепочка). Дешёвая модель по умолчанию, эскалация на дорогую только при неудаче: Llama → Gemini Flash → Claude Sonnet → Claude Opus.
  2. Кэширование промптов. Стабильный префикс (системный промпт + контекст проекта) + один session ID → экономия 60-80% на input-токенах.
  3. Тримминг контекста. Не отправляйте весь файл — только нужные функции. Короткие системные промпты. Резюме вместо полных документов.
  4. Отключайте reasoning там, где не нужен. Модели с reasoning тратят токены на «мысли». Для простых задач — non-reasoning вариант.
  5. Один агент за раз. Три параллельных сессии = 3x токенов. Запускайте параллельно только независимые задачи.
  6. Используйте /undo вместо повторной генерации. Если агент ошибся — откатите и уточните промпт, а не начинайте заново.
  7. Batch-режимы. Если провайдер поддерживает batch API — дешевле на 50%.
  8. Квантованные endpoint'ы. Дешевле, но проверяйте качество (фильтр quantizations).
  9. Локальные модели для рутины. $0 токенов, GPU один раз.
  10. Бесплатные модели для прототипов. 50-1000 req/day по $0.

Правило выбора модели по задаче (шпаргалка)

Как не уходить за лимиты

  • Понимайте лимиты Go: 5-часовой (20%), недельный (50%), месячный (100%). Не сжигайте 20% за 5 часов утром — распределяйте.
  • Используйте дешёвые модели для объёма: DeepSeek V4.1 Flash даёт 34 670 запросов/5ч — идеально для гринда.
  • Выключайте auto-reload (Zen) перед ночными/безлюдными запусками. Иначе баланс станет бездонным. Сделайте баланс жёстким потолком.
  • Устанавливайте max_price в OpenRouter. Запрос упадёт, а не потратит больше плана.
  • Мониторьте расход: CostGoat, OpenRouter Activity, Zen/Go дашборды. Настраивайте алерты при спайках.
  • Считайте 5.5% комиссию OpenRouter. $100 пополнения = $94.50 на инференс.
  • BYOK выгоден только при прямой цене ниже каталогной минус 5%. Считайте перед переключением.
  • Кредиты OpenRouter сгорают через 1 год. Не покупайте впрок.
  • Не используйте frontier-модели для рутины. Это главная причина перерасхода.
  • Держите системный промпт коротким. Каждый токен системного промпта множится на каждый запрос.

Настройка жёсткого потолка (пример)

// OpenRouter: не тратить больше $1 на prompt и $2 на completion
"provider": { "max_price": { "prompt": 1, "completion": 2 } }

// Zen: выключить auto-reload, пополнять вручную
// Go: следить за 5h-лимитом, переключаться на Flash-модели при исчерпании

Антипаттерны (что НЕ делать)

  • ❌ Использовать Claude Opus для форматирования кода или переименования переменных.
  • ❌ Отправлять весь репозиторий в контекст «на всякий случай».
  • ❌ Игнорировать prompt caching (менять начало промпта каждый раз).
  • ❌ Держать auto-reload включённым при автономных ночных запусках.
  • ❌ Плодить 5 параллельных сессий на дорогой модели.
  • ❌ Покупать кредиты OpenRouter впрок (сгорят через год).
  • ❌ Использовать Contributor-модели для проприетарного кода.
  • ❌ Квантованные endpoint'ы для точных задач без проверки.

0. Вайбкодинг: как правильно работать с агентом

Вайбкодинг — это не «написал промпт и забыл». Это итеративный процесс: описали задачу → агент сделал → проверили diff → уточнили. Вот правила, которые экономят часы.

  • Одна задача за раз. «Добавь кнопку выхода» лучше, чем «сделай весь интерфейс».
  • Давайте контекст. Укажите файлы, функции, ограничения. «В src/auth.ts, функция login, добавь проверку email».
  • Критерии успеха. «Должен проходить тест npm test» — агент сам проверит.
  • Используйте AGENTS.md. Создайте файл с правилами проекта (стиль, структура, запреты). OpenCode подгрузит его автоматически.
  • План-режим для сложного. Сначала попросите агента составить план, потом выполняйте по шагам.
  • Проверяйте diff. Всегда смотрите, что изменилось, перед коммитом. /undo — ваш друг.
  • Не плодите сессии. Продолжайте диалог в одной сессии — контекст сохраняется и кэшируется.
  • Давайте примеры. «Сделай как в Button.tsx, но для иконок» — работает лучше абстрактного описания.
Хороший промпт = Роль + Задача + Контекст + Ограничения + Критерий успеха. Пример: «Ты senior-разработчик. Добавь валидацию email в форму регистрации (src/Register.tsx). Не меняй стили. Тесты должны проходить.»

7. Чек-лист старта для чайника

1
Установите OpenCode — одна команда (см. раздел 1).
2
Подключите провайдера — /connect. Выберите OpenRouter (разнообразие) или Go (простота) или прямой ключ.
3
Выберите модель — /models. Для старта: Claude Sonnet или MiniMax M3 или DeepSeek V4.1 Flash.
4
Откройте проект — cd project && opencode. Запустите /init для создания AGENTS.md.
5
Настройте конфиг — модель по умолчанию, разрешения (bash/edit), formatter, LSP.
6
Подключите MCP (по желанию) — GitHub, filesystem, fetch. Через opencode mcp add.
7
Настройте бюджет — выключите auto-reload, поставьте max_price, выберите дешёвую модель по умолчанию.
8
Начните с малого — одна задача, одна сессия. Освойте /undo, /redo, /reload.

8. Частые вопросы

Нужна ли подписка, чтобы использовать OpenCode?

Нет. OpenCode бесплатен. Есть бесплатные модели (OpenRouter free, OpenCode Go промо, локальные). Платите только если хотите конкретную модель.

Что лучше: Go или Zen?

Go — если хотите предсказуемый $10/мес и не думать о ключах (но лимиты сгорают). Zen — если нужна конкретная тяжёлая модель время от времени (платите только за использование).

OpenRouter или прямой ключ?

OpenRouter — если используете несколько моделей и нужен fallback. Прямой ключ — если сидите на одной модели и хотите минимум комиссий.

Можно ли использовать OpenCode офлайн?

Да, с локальными моделями через Ollama/LM Studio. Качество ниже, но $0 и приватно.

Как откатить изменения агента?

/undo и /redo. OpenCode делает git-снапшот перед каждым изменением.

Сколько стоит типичный день разработки?

На дешёвых моделях (DeepSeek Flash, GLM-Flash) — центы. На Sonnet — $1-5. На Opus — $5-20. Зависит от объёма контекста и числа сессий.

Безопасно ли давать агенту доступ к коду?

OpenCode делает снапшоты и поддерживает разрешения (permissions). Для проприетарного кода используйте локальные модели или провайдеров с ZDR (zero data retention).
